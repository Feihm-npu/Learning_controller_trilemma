\section{Assurance-Contract Failure Modes}
\label{sec:lifecycle-attacks}

This section separates four failure modes that arise at different points in
the assurance lifecycle.

\textbf{Nominal-state certification.}
A nominal certificate evaluates an estimate $\hat x(h)$ or a reported sensor
value.  Under FDI, an accepted action may be safe for $\hat x(h)$ but unsafe
for another state in $X_{\mathcal A}(h)$.  Severe-attack safety filters address
this state-semantics failure.

\textbf{Action-only filtering.}
A robust safety filter can project the current action into $K_\Gamma(h)$ when
the kernel is nonempty.  This operation protects the applied action at that
step.  The learner update remains a separate object.  If
$\pi_{\theta_{t+1}}(h)$ leaves $K_\Gamma(h)$, the certificate covers the
filtered action but not the updated action map.  Certified learning must
therefore admit the updated policy as well as the current action.

\textbf{Uncertified learning after rejection.}
When $K_\Gamma(h)=\emptyset$, a severe-attack filter can reject the action or
enter fail-safe mode.  An update computed from the same attacked history then
falls outside the accepted certificate lifecycle.  A fail-safe can protect the
plant while learning is frozen, rolled back, or re-anchored.

\textbf{Protected adaptation, unsafe deployment.}
An adaptation shield can keep every data-collection transition safe while
corrupted reward records influence the learner.  The trusted update rule can
then produce an unsafe raw policy without a physical failure during
adaptation.  Releasing that policy after shield retirement exposes the delayed
effect.  Raw release therefore requires evidence for the policy that receives
action authority.

These failure modes require separate metrics.  An \emph{unsafe certified action}
counts accepted certificates whose applied action is unsafe for some plausible
state.  A \emph{stale certified policy} counts accepted certificates for which
the updated raw policy leaves the kernel.  \emph{Uncertified learning} counts
nontrivial updates after certificate rejection.  End-to-end studies
add delayed deployment violations, admission coverage, paired clean/poison
outcomes, update fraction, intervention, reward, and certificate runtime.
